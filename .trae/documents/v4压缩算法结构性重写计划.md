# 歌曲压缩算法 v4.0 结构性重写计划

## 摘要

按 v4.0 设计文档将现有歌曲压缩从「两模型打分」架构重构为**结构分层感知压缩**：
Stage 0 物理模型 → Stage 1 预处理 → Stage 2 结构分析（6 模式检测）→ Stage 3 候选生成（13 类）→ Stage 4 成本评估 → Stage 5 贪心选择 + 7 不变式校验回滚 → Stage 6 审计输出。核心修正：伪延音能量补偿合并、闻阈删除、稀疏/声部绝对下限、funky/密集鼓点模式、跨音色掩蔽、参数集中管理。

保持对外契约不变：`window.compressSongCore(notes, quality, model, ctx)` 与 `window.compressSongEstimate(notes, quality, opts)` 的签名/返回结构不变，轨道分组、空洞填补(`dedupeReorderNotes`)、单次撤销逻辑全部保留。质量滑块改为 **5 档压缩等级**（近乎无损 q=0.99 / 高质量 q=0.60 / 中等质量 q=0.40 / 较低质量 q=0.20 / 最低质量 q=0.05），删除量由 q 驱动（≈ 删除去重后音符的 (1-q) 比例），99% 档仅完全去重。

## 现状分析

现有实现 `nbs_client.js:2639-2924`（`window.compressSongCore` 的 IIFE）：
- **两模型**：`rankHeuristic`/`rankPerceptual` 全库打分 → 升序排序 → 按 budget 删前 N 个。
- **删除量**：`(1-Q) × 各组去重后音符数`；99% 档仅完全去重（`tick:instrument:key`）。
- **轨道分组**：exclude（完全不动）/ lighten（配额减半）/ normal。
- **空洞填补**：`window.dedupeReorderNotes(kept, batch)` 每批删除后调用。
- **保护方式**：仅通过高权重打分（无硬不变式）。

v4.0 带来的差距：无物理感知、无结构分析、无硬不变式、散落魔数、无审计、无模式自适应。

## 用户已确认决策

| 决策 | 结论 |
|---|---|
| 落地方式 | **结构性重写**（按 v4.0 完整重构判断引擎） |
| `model` 参数 | 保留，退化为「成本权重两组预设」（heuristic / perceptual），删除集合**允许不同**（用户 2026-09-19 放宽：不要求两模型删除数量一致，但要保证效果） |
| 质量滑块 | 由 7 档比例改为 **5 档压缩等级**（近乎无损/高质量/中等质量/较低质量/最低质量） |
| 轨道分组 / 单次撤销 | 保持不变 |
| 空洞填补 | 每个批准的候选批次后调用 `dedupeReorderNotes` |

## 5 档压缩等级语义（2026-09-19 决策）

| 档位 | q | 语义 | 说明 |
|---|---|---|---|
| 近乎无损 | 0.99 | 仅完全去重（tick:instrument:key） | 等效旧「消除重复音符」，最安全 |
| 高质量 | 0.60 | 保守有损：删最低优先级候选，结构音受 c_max 强保护 | 替代旧 60-80% 区间 |
| 中等质量 | 0.40 | 常规有损：节奏/装饰音削减 | 替代旧 40% 档 |
| 较低质量 | 0.20 | 强力有损：含内声部/重复段落 | 替代旧 10-20% 区间 |
| 最低质量 | 0.05 | 极限压缩：所有可删候选，黄色警示 | 替代旧 1% 档，UI 显示警示 |

- **删除量契约**：目标 = `round(去重后参与组音符数 × (1-q))`；99% 档精确等于纯去重量。
- **持久化迁移**：旧 localStorage 存百分比数字（`"40"`），新版存档名（`"中等质量"`）。读取顺序：先按档名匹配 → 失败则把旧数字按最近 q 反查档位 → 默认 0（近乎无损），保证老用户回退安全。
- **预估=实际**：`compressSongEstimate` 接受 `opts.model`，与 `compressSongCore` 共享 `selectPlan`，任一档位预估均与最终删除一致（回归已断言）。

## P0 评审结论（2026-09-19 已落地）

| 编号 | 问题 | 结论 |

### 模块三：Stage 2 结构分析

全部输出写入 `ctx`（扩展内部 ctx），供后续候选/成本阶段读取：

```js
  var avgMult = ...;
  var chordRatio = ...;
  var chordLow = avgMult > 1.5;                  // 简化：存在同 tick 多音即视为潜在和弦

  //   条件：同 instrument、同 eff_pitch(半音)、相邻间隔 ≤ 2 tick、忽略过程中混入它 pitch 的同乐器音
  //   输出: [{notes:[n0,n1,...]、origVel、compFactor}]

  // 2f 模式标记
  var funky = avgMult > 3.5 && chordRatio > 0.6;
  var densePerk = percDensity(notes) > P.dDense;

```

旋律声部 `melodyDominant`：按 instrument×音域聚类，取占比最大声部，若 >80% 则标记其层为 melody（禁删）。声部聚类采用轻量近似：以「主拍触发密度最高、音高最集中」的层组合作为 melody（不引入完整 DBSCAN，避免工程爆炸，见「假设与决策」）。

### 模块四：候选生成（Stage 3，13 类）

为每个音符组生成候选对象 `{id, notes:[被删引用], cost, class}`。激活阈值 + 模式修正遵循 v4.0 §5 总表。候选在「去重后、进入贪心前」批量生成一次。

```js
function generateCandidates(kept, ctx) {
  // C0 同 tick:instrument:key 去重（保留 effVol 最大者；全 Q）
  // C1 同音色类八度/同度重复（Q<0.95；funky 下仅删完全一致和弦重复）
  // C2 伪延音能量补偿合并（Q<0.90；取 analyzeStructure 的 pseudoGroups）
  // C3 伴奏五音（Q<0.75；依赖和声；funky 成本×2.5）
  // C4 伴奏三音（Q<0.80；依赖和声）
  // C5 装饰音（Q<0.85；部分和声；sparse 禁用）
  // C6 伴奏节奏密度减半（Q<0.70；sparse 禁用）
  // C7 Hat 网格稀疏化（Q<0.65；densePerk 放宽阈值）
  // C8 内声部整段静音（Q<0.45；sparse 禁用）
  // C9 ghost snare / 稳态 tom 削减（Q<0.50）
  // C10 旋律弱拍短音剪枝（Q<0.30；melodyDominant 禁用）
  // C11 完全重复段落去重（Q<0.45）
  // C12 闻阈删除（effVol*100 < P.inaudibleVol，Q≥0.9 自动启用，成本 0，不计压缩率）
  // 阈值即 CLS_Q（A3 重标定，见「P0 评审结论」）；排序键 = 单位成本 cost/del.length（A1）
  // 排除约束：不含 exclude 层音符；lighten 层候选成本×2（等效配额减半）
  // 每个候选最多删若干远端音符（如 C6 可一次删多音，均记入 notes）

```

候选激活由 `q` 与文档阈值比较决定；`q>=0.99` 时仅保留 C0（等价完全去重）。**`a tonal` 模式**：禁用 C3/C4/C8。**sparse**：禁用 C5/C6/C7/C8/C11。

### 模块五：成本评估（Stage 4）

```js
function candidateCost(c, ctx) {
  // 各维 Δ 计算（v4.0 §6.1）
  // Δharm: 末实例=1.0 / 五音有兄弟=0.2(funky 0.5) / 弱拍非和弦音=0.05
  // Δrhythm: 强拍=1.0 / backbeat=0.8 / 弱拍=0.15（grid_neutral 全 0.4）
  // Δmelody: >2拍空隙=1.0 / >8ve跳进=0.8 / 结构音=0.7
  // Δtexture: tick清空=1.0 / Voice间隔>2拍=0.8
  // Δtimbre: 乐器2小节窗口末实例=0.6
  // 掩蔽 μ_local：仅 VOICE_CLASS_PITCHED 内跨音色计算（打击乐除外）
  //   Δharm *= (1 - 0.3 * μ_local)
  var d = [dHarm(·masked), dRythm, dMelody, dTexture, dTimbre];
  var cost = dot(d, P.costWeights);       // perceptual 权重预设
  // heuristic 预设：weights = [0.30,0.25,0.20,0.15,0.10] 一致（仅快速路径）
  // lighten 层: cost *= 2；exclude: 不生成
  return { base: cost*0.9, heuristic: cost, perceptual: cost };  // 见 model 映射
}
```

**model 映射（结构性重写下如何保住现有 UI）**：候选生成与不变式对所有 model 相同，仅 `cost` 数值用 `P.costWeights` 的两种预设区分（heuristic = 朴素权重；perceptual = 朴素权重 + 掩蔽/密度微调）。因此两模型**候选集合相同、删除量相同**，只有保留顺序不同——与 UI 提示一致。

### 模块六：贪心选择 + 不变式回滚（Stage 5）

```js
function selectCandidates(cands, kept, q, ctx) {
  cands.sort(按 model 的 cost 升序); remove = []; removedSet = new Set();
  failure = 0;
  for (c of cands) {
    if (failure >= P.failBudget) break;
    if (violatesInvariants(c, removedSet, kept, ctx, q)) { failure++; continue; }
    // 字节收益 guard：收益须 > 0（v4.0 §6.3）
    if (bytesSaved(c) <= 0) { continue; }
    applyCandidate(c, removedSet, kept); remove.push(c); failure = 0;
  }
  return remove;   // 每一步后调用方 flushBatch(dedupeReorderNotes)
}
```

7 项不变式（`violatesInvariants`），违反则跳过并计入 failure budget：

- **I1** kick（instrument 2）候选一律拒（不删除）。
- **I2** backbeat 军鼓（instrument 3 位于第 2/4 拍：`floor(tick/tpb) % 2 === 1`）拒。
- **I3** 和弦三柱：每个窗口 ≥1 root + 1 (3rd/7th)（若原存在）；删除后不足则拒。
- **I4** tick 非空：原非空 tick 删除后为空则拒。
- **I5** L1 双重：Voice 删除比 < `maxRemovalPerVoice(q)` **且** 剩余 ≥ `P.voiceMinAbs(3)`。
- **I6** 旋律锚点：每 4 拍窗口保留 ≥1 melody 长音。
- **I7** 闻阈候选成本 0 且不计压缩率，允许删除（C12 触发）。

`maxRemovalPerVoice(q) = clamp(0.5 + 0.4*(1 - q), 0.2, 0.9)`（B8 改回 v3.0 语义：最低档上限 0.9，高质量档上限 0.66）。

### 模块七：预算与删除量（与 UI 契约衔接）

删除量由 5 档压缩等级的 q 驱动（维持「档位 ≈ 删除 (1-q) 比例」与预估一致性）：
- 目标删除 = `round(cnt * (1 - q))`（cnt=去重后参与组音符数；lighten 组 ×0.5）。
- **排序（A1）**：候选按单位成本 `cost/del.length` 升序消费，组级大宗候选优先。
- **截断（A2）**：`cMax = P.cMaxBase + P.cMaxScale × (1-q)`；`baseCost > cMax` 的候选跳过，防止中高档乱删结构音。
- 循环直到累计删除数 ≥ 目标 **或** 候选耗尽 **或** 不变式回滚预算耗尽；预算 break 条件为 `removedCount() >= target && !cand.inaudible`。
- **近乎无损档（q=0.99）**：仅 C0（完全去重），不发生有损删除。

`compressSongEstimate` 重写为其与最终实际尽可能一致：`deleted = dup(各轨) + min(round(...), 可删候选可生成的上限估算)`。由于候选激活会令实际≤纯 budget，预估采用「budget 与候选可删上限取小」，避免弹窗显示不符。

### 主管线（重写 `compressSongCore`）

保留轨道分组 → 阶段1 完全去重（同现有）→ 分析（`analyzeStructure`）→ 生成候选（`generateCandidates`）→ 评估（`candidateCost`）→ 贪心+回滚（`selectCandidates`）→ **每批 flushBatch 调 `dedupeReorderNotes`** → 汇总。

```js
function compressSongCore(notes, q, model, ctx){
  ctx = ctx||{}; var tpb = resolveTpb(ctx);
  var excludeSet = toLayerSet(ctx.excludeLayers), lightenSet = toLayerSet(ctx.lightenLayers);
  var kept = notes.slice(), removed = [], moved = 0;
  flushBatch = ...   // 同现有：Set 引用集 + dedupeReorderNotes + removed.push
  // 阶段1 完全去重（exclude 不参与）
  ...同现有...
  // 阶段2 结构分析 + 候选 + 贪心（99% 跳过）
  if (q < 0.99){
    var structure = analyzeStructure(kept, tpb, ...);
    var cands = generateCandidates(kept, q, structure, ctx);
    var plan = selectCandidates(cands, kept, q, ctx, model);
    flushBatch(plan.removedNotes);

```

`audit` 是返回对象的**新增可选字段**——向后兼容（调用方忽略即可），当 `ctx.audit=false` 时省略，避免破坏 `doCompressSong` 现有逻辑。

### 字节收益（v4.0 §6.3）

`bytesSaved(c)` 用近似：被删音符数 × 平均每音符 NBS 字节成本（header+数据段长度）。精确值不可得（需重编码整段），采用**单调守恒近似**即可：保证收益>0 恒成立即可放行（只要候选确实删了音符就总是字节减少），因此该 guard 主要防「删 0 音符的候选」，开销极低。

## 假设与决策

- **无 layer_volume 字段**：I7 闻阈与 effVol 用 `velocity/100` 近似（v4.0 的 `layer_volume×velocity` 在现数据模型下不可得）。注释标注为近似。
- **LogicalVoice/ChordSegment 轻量化**：不引入完整 DBSCAN/层次聚类（前端性能风险），用「instrument×音域 + 主拍触发密度」近似声部角色；ChordSegment 用 4 拍窗口同 tick 多音统计近似。功能目标（声部保护、和弦保持、稀疏保护、肩模式检测）全部达成，只是分析器更轻。
- **model 权重预设**：heuristic 与 perceptual 在同一候选集上仅 cost 权重/掩蔽微调不同 → 删除集合允许不同（用户放宽），但两模型各自满足预算/守恒/效果保证，差异用于「感知更保守」的 UI 提示。
- **99% 档 = 仅 C0**：保持「99% ≡ 原消除重复音符」语义。
- **audit 新增可选字段**：不破坏 `doCompressSong` 现有返回处理。
- **参数为初始值**：标注 `[UNVERIFIED]`，文案/文档声明需实验校准。
